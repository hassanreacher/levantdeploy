# LevantBase — self-hosted backend projects inside LevantDeploy (read this first)

LevantBase gives every LevantDeploy user "backend projects": a dedicated Postgres database + Auth + auto REST API + Realtime + Storage + Edge Functions + a full database Studio — built from the **official open-source self-hosting stack** (Apache-2.0) vendored in `base-stack/upstream/` (github.com/supabase/supabase `docker/`, pinned commit in UPSTREAM.txt). We do NOT call any hosted service. Apps use the standard open-source client libraries (`@supabase/supabase-js` etc. are MIT) pointed at the project's own URL — 100 % API compatible because the same server components run.

It is part of LevantDeploy: same users, teams, roles, login, tokens, audit log, notifications, AI agent, CLI, dashboard shell and design. NEVER push to git remotes. Never copy real secrets.

## Product naming in UI
"LevantBase" (nav item "Base" next to the team's projects). Each backend project = **Base project** (`ref` = 20-char lowercase id). Studio = "Studio" (keep upstream Apache notices; don't use the upstream trademark/logo as our brand).

## Architecture
- One **stack per Base project**, rendered from the upstream compose template into `STORAGE_DIR/base/{ref}/` (compose file + `.env` + volumes copied from upstream `volumes/`) and run as compose project `lb_{ref}` on its own network `lb_{ref}_net`, joined to `levant_net` ONLY by the gateway container (so Caddy can reach it). Services: db (supabase/postgres), auth, rest, realtime, storage (file backend on a per-project volume), imgproxy, meta, functions (edge-runtime), api-gw (upstream envoy/kong config), supavisor pooler (optional per plan), studio (started on demand, stopped after idle). Logflare/vector analytics: off by default (optional later). Resource limits per service from the plan.
- Secrets per project generated at create time: POSTGRES_PASSWORD, JWT_SECRET (≥ 40 chars), ANON_KEY + SERVICE_ROLE_KEY (HS256 JWTs signed with JWT_SECRET, role anon/service_role, iss "levantbase", long exp), DASHBOARD creds unused (our auth), SECRET_KEY_BASE, VAULT_ENC_KEY, PG_META_CRYPTO_KEY, LOGFLARE tokens dummy. Stored encrypted (`encryptJson`) in DB.
- Public endpoints (Caddy, on-demand TLS):
  - API: `https://{ref}.{BASE_DOMAIN}` → project api-gw (BASE_DOMAIN defaults to `base.{PLATFORM_DOMAIN}`; wildcard DNS `*.base.domain`). Paths exactly as upstream: `/auth/v1`, `/rest/v1`, `/graphql/v1`, `/realtime/v1`, `/storage/v1`, `/functions/v1`, `/pg` (service key only). Optional custom API domain (reuse LevantDeploy domains lib).
  - Studio: `https://studio-{ref}.{BASE_DOMAIN}` gated by Caddy `forward_auth` → control `/api/internal/base/studio-auth` which checks a host-only signed cookie issued via SSO hand-off from the dashboard (`/api/v1/base/projects/:ref/studio` → one-time token → `studio-{ref}.../__levant/sso?t=` sets cookie → redirect `/project/default`). Only team members with role ≥ MEMBER (VIEWER read-only not possible in Studio → require MEMBER).
  - Database direct connections: optional public TCP port per project (plan-gated, off by default) via the pooler; connection strings shown in dashboard.
- Control plane (Next.js app `control/`): Prisma models `BaseProject` (teamId, ref, name, status PROVISIONING/ACTIVE/PAUSING/PAUSED/RESTORING/UPGRADING/ERROR/DELETING, secretsEnc, versions Json, settings Json (auth/smtp/url config/limits), dbPublicPort?, lastActivityAt, createdById), `BaseBackup`, `BaseFunction` (name, slug, verifyJwt, sourcePath, version), `BaseUsageSample`, `BaseEvent`. Worker queue `base` with jobs: provision, pause, resume, restart(service?), upgrade, delete, backup, restore, studio-start/stop, usage-sample, auto-pause-inactive.
- Library contract (`control/src/lib/base/`): `createBaseProject({teamId,name,dbPassword?,createdById})`, `getBaseProject(ref)`, `baseKeys(ref)` → {url, anonKey, serviceRoleKey (privileged)}, `connectionStrings(ref)`, `runSql(ref, sql, {role})` (via pg direct as postgres or via meta), `stackAction(ref, action)`, `baseUsage(ref)`, `projectUrl(ref)`, `studioUrl(ref)`.

## Plans & limits (both products; owner-editable later, defaults mirror Vercel Hobby/Pro + Supabase Free/Pro)
`Plan` model (slug, name, priceMonthly (display only, no billing yet), limits Json) + `Team.planId`. Default plans:
- **Hobby/Free**: Deploy — 200 projects, 100 deployments/day, 1 concurrent build, 45 min build timeout, 100 GB bandwidth/mo, 4 GB build memory, 1 team member (owner only), preview deployments on, custom domains 50/project; Base — 2 active Base projects, 500 MB database, 1 GB file storage, 50 MB max upload, 50,000 MAU, 5 GB egress/mo, 500k function invocations/mo, 10 functions, paused after 7 days without API activity, daily backups kept 0 (manual dump only), no pooler public port, shared CPU (0.5 CPU / 1 GB RAM total per project).
- **Pro**: Deploy — unlimited projects, 6000 deployments/day, 12 concurrent builds, 1 TB bandwidth, unlimited members; Base — unlimited projects, 8 GB DB, 100 GB storage, 5 GB max upload, 100,000 MAU, 250 GB egress, 2M invocations, 500 functions, never paused, daily backups kept 7, public DB port allowed, 2 CPU / 4 GB RAM per project.
- **Team/Enterprise**: same as Pro with higher numbers; platform owner's own team is unlimited.
Enforcement: hard caps on creation (projects, functions, members, deployments/day, concurrent builds, upload size), soft caps metered monthly (bandwidth, egress, MAU, DB size, storage) → warning at 80 %, email at 100 %, then restrict (Base: DB set read-only via `default_transaction_read_only` for over-size DB; storage uploads blocked; Free projects paused; Deploy: new deployments blocked) — all configurable per plan with an "enforce" flag.
